# Google Play「資料安全性」與其他政策表單（草稿）

依 App 實際行為整理（2026-10-16，版本 0.1.0）。送出前請再對照 Play Console 的最新題目；題目文字可能和這裡略有不同。

## App 的實際行為（填表依據）

| 行為 | 資料 | 傳到哪裡 | 誰觸發 |
|---|---|---|---|
| 清理連結 | 連結 | 不離開手機 | 使用者 |
| 展開短網址（可在設定關閉） | 短網址本身 | 該短網址服務（例如 bit.ly、Facebook、Threads） | 使用者處理該連結時 |
| 下載規則 | 不含使用者資料 | GitHub Pages | App 自動（每天最多一次） |
| 歷史紀錄 | 處理過的連結 | 只存在手機（Android 已關閉系統備份） | 使用者可關閉、清除 |
| 回報問題 | 連結、App 與規則版本 | 使用者自己的郵件 App，由使用者決定是否寄出 | 使用者 |
| 權限 | 只有 `INTERNET` | — | — |

沒有帳號、廣告、分析、崩潰回報或任何第三方 SDK 會傳送資料。

## 資料安全性

| 問題 | 建議答案 | 說明 |
|---|---|---|
| 應用程式是否收集或分享任何必要的使用者資料類型？ | **否** | 見下方「判斷理由」 |
| 傳輸中的資料是否經過加密？ | **是** | 只使用 HTTPS；短網址一律改用 https 請求 |
| 是否提供使用者要求刪除資料的方式？ | 不適用（沒有收集） | 歷史紀錄可在 App 內清除 |

### 判斷理由與保守的替代方案
- **規則下載**不含使用者資料，不算收集
- **回報問題**是打開使用者自己的郵件 App，App 本身不傳送任何資料；要不要寄出由使用者決定
- **短網址展開**會把該短網址送到它所屬的服務，這是使用者處理該連結時的直接結果，跟在瀏覽器打開該連結相同。Google 對「使用者主動發起、可合理預期的傳輸」有例外，所以建議填「否」
- **不確定時的保守做法**：如果審核方認為短網址展開算「分享」，可以改填：
  - 資料類型：「應用程式活動 → 其他使用者產生的內容」或「網頁瀏覽 → 網頁瀏覽記錄」
  - 分享對象：第三方（短網址服務）
  - 用途：應用程式功能
  - 是否為選用：是（可在設定關閉）
  - 不會在處理後保留（App 不保留，對方服務如何處理不在 App 控制範圍）
