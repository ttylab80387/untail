# 歷史紀錄改版：「我分享過什麼」— 設計文件

- 日期：2026-10-15
- 狀態：待審閱
- 目標版本：1.1（與內購一起；第一版上架不含）

## 1. 目標

### 1.1 為什麼要改
用戶會想用歷史紀錄回頭看「我分享過哪些東西」。目前的歷史紀錄只是一串網址：

- 看不出是哪個網站、哪一篇（`instagram.com/p/C8xYz…`）
- 只保留最近 200 筆，舊的自動刪除
- 沒有搜尋、沒有分組，只能一直往下捲

### 1.2 成功的樣子
打開歷史頁，一眼看出「今天分享了 Threads 上 @某人 的貼文、一支 YouTube 影片」，能用關鍵字找到上個月分享的東西。

### 1.3 原則（沿用既有承諾）
- **不連到目標網站**：除了第 6 節的「標題與預覽圖」（另外決定、預設關閉），所有功能都只用手機上已有的網址資料
- 歷史只存在本機，可關閉、可清除（隱私政策 p4 不變）
- 免費版要「好用」，付費版是「進階」：不把基本可用性鎖在付費牆後面

## 2. 功能與免費 / 付費劃分

| # | 功能 | 免費 | Pro | 需要連網 |
|---|---|---|---|---|
| F1 | 網站名稱與圖示 | ✅ | ✅ | 否 |
| F2 | 作者／版面（從網址解析） | ✅ | ✅ | 否 |
| F3 | 依日期分組 | ✅ | ✅ | 否 |
| F4 | 搜尋 | ✅ | ✅ | 否 |
| F5 | 保留筆數 | 最近 **500** 筆 | **不限** | 否 |
| F6 | 匯出 CSV | — | ✅ | 否 |
| F7 | 標題與預覽圖 | — | 不在本設計範圍（見第 6 節） | **是** |

### 2.1 劃分理由
- F1–F4 決定歷史紀錄「能不能用」，放免費。鎖起來只會讓免費版顯得殘缺，評價變差
- 免費保留筆數從 200 提高到 500：空間成本很小（每筆約 1–2 KB），約可涵蓋數個月的一般使用
- **不限筆數**與**匯出**是「長期把它當紀錄本」的人才需要的，適合付費。這兩個都不違反隱私承諾
- 付費是一次性買斷（US$0.99，見內購規劃），不是訂閱

### 2.2 「付費才保留資料」的處理
為避免「不付錢就刪你資料」的觀感：
- 免費版達到 500 筆時，歷史頁頂端顯示一行說明：「保留最近 500 筆，較舊的會自動刪除。Pro 可保留全部。」
- **購買 Pro 之後不會救回已刪除的紀錄**，說明文字要寫清楚，避免誤會

## 3. 各功能細節

### F1 網站名稱與圖示
- 由 `cleanUrl` 的網域判斷，純函式 `describeLink(url)`，不連網
- 已知平台對照表（程式內建，之後可擴充）：

| 網域 | 顯示名稱 | 圖示 |
|---|---|---|
| threads.com / threads.net | Threads | `logo-threads`（Ionicons 沒有的話用 `at`） |
| instagram.com | Instagram | `logo-instagram` |
| facebook.com / fb.watch | Facebook | `logo-facebook` |
| x.com / twitter.com | X | `logo-x`（沒有則 `logo-twitter`） |
| youtube.com / youtu.be | YouTube | `logo-youtube` |
| tiktok.com | TikTok | `logo-tiktok` |
| reddit.com | Reddit | `logo-reddit` |
| linkedin.com | LinkedIn | `logo-linkedin` |
| pinterest.com | Pinterest | `logo-pinterest` |
| xiaohongshu.com | 小紅書 | `book-outline` |
| bilibili.com | bilibili | `tv-outline` |
| shopee.tw / shopee.* | 蝦皮 | `cart-outline` |

- 其他網站：顯示去掉 `www.` 的網域（例如 `news.ltn.com.tw`），圖示用 `globe-outline`

### F2 作者／版面
只解析網址裡本來就有的資訊，找不到就不顯示：

| 平台 | 網址樣式 | 顯示 |
|---|---|---|
| Threads | `/@{user}/post/…` | `@user` |
| X | `/{user}/status/…` | `@user` |
| TikTok | `/@{user}/video/…` | `@user` |
| YouTube | `/@{handle}…` | `@handle`（`watch?v=` 沒有作者，不顯示） |
| Instagram | `/{user}/`（個人頁）；`/p/…`、`/reel/…` 沒有作者 | `@user` 或不顯示 |
| Reddit | `/r/{sub}/…`、`/u/{user}/…` | `r/sub`、`u/user` |
| Facebook | `/{page}/posts/…`（`/share/`、`photo.php` 不顯示） | `page` |

- 另外標示內容類型（可選）：貼文、影片、Reel、個人頁。只在能從路徑明確判斷時顯示

### F3 依日期分組
- 分組：今天、昨天、本週（7 天內）、更早則以「年／月」分組（例：2026 年 9 月）
- 用 `SectionList`；分組邏輯為純函式 `groupByDate(entries, now, locale)`，可單元測試
- 時間用手機的本地時區

### F4 搜尋
- 歷史頁頂端搜尋框，比對：乾淨網址、網站名稱、作者
- SQL `LIKE` 查詢（見第 4 節的新欄位），輸入時延遲約 200ms 再查
- 結果一樣依日期分組

### F5 保留筆數
- `HISTORY_LIMIT` 由 200 改為免費 500；Pro 時不刪除
- Pro 用戶的清單改為分頁載入（一次 100 筆，捲到底再載入），避免一次讀出上萬筆

### F6 匯出 CSV（Pro）
- 歷史頁右上選單 →「匯出」→ 系統分享選單（可存到檔案、寄給自己）
- 欄位：日期時間、網站、作者、**乾淨網址**、移除的參數名稱
- **不匯出原始網址**（含追蹤碼與分享者代碼），避免匯出檔外流時洩漏
- CSV 正確處理逗號、引號、換行；UTF-8 加 BOM，讓 Excel 正確顯示中文
- 需要新增 `expo-file-system`、`expo-sharing`（Expo 官方套件）

## 4. 資料結構

`history` 表新增欄位（`ALTER TABLE ADD COLUMN`，由 `migrate()` 偵測後執行）：

| 欄位 | 型別 | 說明 |
|---|---|---|
| `site` | TEXT | F1 的顯示名稱，寫入時計算 |
| `author` | TEXT NULL | F2 的作者，寫入時計算 |

- 寫入時計算，方便 SQL 搜尋；舊資料在 migrate 時一次補齊（backfill）
- 對照表日後更新時，可再跑一次 backfill（以 `kv` 記錄版本號）
- 預留 `title TEXT NULL` **不加**，等第 6 節決定後再說（YAGNI）

## 5. 付費狀態（isPro）

- 目前程式裡**還沒有** `isPro`。本設計只依賴一個布林值 `isPro`，由 `AppContext` 提供
- 購買、恢復購買、商店設定屬於另一份「內購」設計，不在本文件範圍
- 開發期間預設 `false`；測試 Pro 功能用 debug build 的開關，不放進正式版

## 6. 不在本設計範圍：標題與預覽圖（F7）

需要連到目標網站下載網頁（Open Graph），與「不連目標網站」的承諾衝突，FB、IG、Threads 常常只回傳登入頁，小紅書在台灣被封鎖。若要做，另開設計，至少要：預設關閉、只用乾淨網址抓、更新隱私政策。

## 7. 測試

- 單元測試（vitest）：
  - `describeLink`：每個平台各取 2–3 個網址（含找不到作者的情況），以及未知網域
  - `groupByDate`：固定 `now` 與時區，跨日、跨月、跨年的邊界
  - `migrate` + backfill：用 node:sqlite 建舊表、塞資料、遷移後檢查新欄位
  - 搜尋查詢：網址、網站、作者三種比對；萬用字元 `%`、`_` 要跳脫
  - CSV：逗號、引號、換行、中文、BOM
  - 保留筆數：免費刪到 500、Pro 不刪
- 手動（Android 真機 + iOS 模擬器）：分組顯示、搜尋、500 筆提示、匯出到檔案 App

## 8. 需要注意的地方（Review Focus）

1. **舊資料遷移**：已經有歷史紀錄的用戶升級後，紀錄不能消失或錯亂；backfill 失敗時要能照常顯示（`site` 空白就即時計算）
2. **一筆壞資料不能讓整個清單變空白**（既有的已知問題：`toEntry` 解析 JSON 失敗會讓整頁失敗），這次一起修
3. **搜尋的特殊字元**：使用者輸入 `%`、`_`、`'` 不能讓查詢出錯或比對到全部
4. **大量資料**（Pro、上萬筆）：捲動和搜尋不能卡頓
5. **匯出內容**：確認沒有原始網址和分享者代碼

## 9. 範圍外

- 標籤、收藏、備註
- 雲端同步、跨裝置
