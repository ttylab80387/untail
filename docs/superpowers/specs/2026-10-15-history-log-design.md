# 歷史紀錄改版：「我處理過的連結」— 設計文件

- 日期：2026-10-15（同日依 codex / agy 設計審查修訂）
- 狀態：待審閱
- 目標版本：1.1（與內購一起；第一版上架不含）

## 1. 目標

### 1.1 為什麼要改
用戶會想用歷史紀錄回頭找「之前那個連結」。目前的歷史紀錄只是一串網址：

- 看不出是哪個網站、哪一篇（`instagram.com/p/C8xYz…`）
- 只保留最近 200 筆，舊的自動刪除
- 沒有搜尋、沒有分組，只能一直往下捲

### 1.2 定位：「處理過」，不是「分享過」
Untail 不知道連結最後有沒有被貼出去：自動處理剪貼簿、按了取得乾淨連結卻沒分享，都會留下紀錄；開啟系統分享選單也不代表內容送達。因此本版一律稱為「**我處理過的連結**」，文案不宣稱「你分享了什麼」。

### 1.3 成功的樣子（可驗收）
- 一眼看出每筆是哪個網站，網址裡有帳號的顯示帳號
- 能用**網站、網址裡的帳號、處理時附帶的文字、日期**找回連結
- 不承諾能用貼文內容搜尋：網址本身沒有標題時，只能靠附帶文字（見 F4）

### 1.4 原則（沿用既有承諾）
- **不連到目標網站**：所有功能只用手機上已有的資料。標題與預覽圖不在本設計（第 6 節）
- 歷史只存在本機，可關閉、可清除
- **不拿「刪除資料」當付費誘因**：免費與 Pro 保留相同的紀錄
- 免費版要好用，Pro 是加值

## 2. 功能與免費 / 付費劃分

| # | 功能 | 免費 | Pro | 需要連網 |
|---|---|---|---|---|
| F1 | 網站名稱與圖示 | ✅ | ✅ | 否 |
| F2 | 網址中的帳號／版面 | ✅ | ✅ | 否 |
| F3 | 依日期分組 | ✅ | ✅ | 否 |
| F4 | 搜尋（含處理時附帶的文字） | ✅ | ✅ | 否 |
| F5 | 保留筆數 | 最近 **5,000** 筆 | 同左 | 否 |
| F6 | 匯出 CSV | — | ✅ | 否（但檔案會交給使用者選擇的 App） |

### 2.1 劃分理由
- F1–F5 決定歷史紀錄能不能用，全部免費
- 保留筆數**免費與 Pro 相同**。Untail 沒有伺服器成本，5,000 筆約數 MB。上限只是防止資料庫無限成長的安全值，大約是每天處理 10 個連結、一年多的量
- 這樣也**完全避開**「付費狀態尚未確認時誤刪 Pro 用戶紀錄」的風險：刪除與否不再依賴 `isPro`
- Pro 的歷史相關賣點是**匯出**；之後可再加進階篩選（例如只看某網站）或需自行開啟的標題預覽。Pro 整體內容（含其他非歷史功能）由內購設計決定
- 付費是一次性買斷（US$0.99），不是訂閱

### 2.2 上限說明
- 歷史頁在達到 4,500 筆時，頂端顯示一次：「歷史會保留最近 5,000 筆，較舊的會自動刪除。」可關閉
- 刪除與清除全部，所有使用者都可以用

## 3. 各功能細節

### F1 網站名稱與圖示
- 純函式 `describeLink(url)`，**絕不拋錯**：空字串、無法解析的網址一律回傳 `{ site: 網域或原字串, author: null }`
- 用 URL 解析器取得 hostname（轉小寫、去掉結尾的 `.`），以**官方網域清單**比對：等於該網域，或是它的子網域（`*.instagram.com`）。不得用「包含字串」比對，`instagram.com.evil.test` 不能被認成 Instagram
- 已知平台：

| 官方網域 | 顯示名稱 | 圖示 |
|---|---|---|
| threads.com、threads.net | Threads | `logo-threads`（Ionicons 沒有則 `at`） |
| instagram.com | Instagram | `logo-instagram` |
| facebook.com、fb.watch | Facebook | `logo-facebook` |
| x.com、twitter.com | X | `logo-x`（沒有則 `logo-twitter`） |
| youtube.com、youtu.be | YouTube | `logo-youtube` |
| tiktok.com | TikTok | `logo-tiktok` |
| reddit.com | Reddit | `logo-reddit` |
| linkedin.com | LinkedIn | `logo-linkedin` |
| pinterest.com | Pinterest | `logo-pinterest` |
| xiaohongshu.com | 小紅書 | `book-outline` |
| bilibili.com | bilibili | `tv-outline` |
| shopee.tw、shopee.com、shopee.sg、shopee.co.th 等**明確列出**的蝦皮網域 | 蝦皮 | `cart-outline` |

- 其他網站：顯示去掉 `www.` 的 hostname，圖示用 `globe-outline`

### F2 網址中的帳號／版面
- 文案稱「帳號」或「版面」，不稱「作者」：只能確定網址裡寫了什麼，不能確定真正作者
- 規則必須**完整錨定路徑**，帳號要符合該平台的帳號格式，並排除保留路徑；不符合就不顯示：

| 平台 | 符合的樣式 | 顯示 | 保留路徑（不是帳號） |
|---|---|---|---|
| Threads | `/@{user}/post/{id}` | `@user` | — |
| X | `/{user}/status/{id}` | `@user` | `i`、`home`、`explore`、`search`、`settings`、`intent` |
| TikTok | `/@{user}/video/{id}`、`/@{user}/photo/{id}` | `@user` | — |
| YouTube | `/@{handle}`、`/@{handle}/…` | `@handle` | `watch?v=`、`shorts/` 不顯示 |
| Instagram | `/{user}/`（只有一段的個人頁） | `@user` | `p`、`reel`、`reels`、`tv`、`stories`、`explore`、`accounts`、`direct` |
| Reddit | `/r/{sub}/…`、`/u/{user}/…`、`/user/{user}/…` | `r/sub`、`u/user` | — |
| Facebook | `/{page}/posts/…`、`/{page}/videos/…` | `page` | `groups`、`watch`、`events`、`share`、`photo.php`、`story.php`、`profile.php`、`permalink.php` |

- 百分比編碼要先解碼；解碼失敗就不顯示

### F3 依日期分組
- 分組：今天、昨天、**最近 7 天**、更早以「年／月」分組（例：2026 年 9 月）。以本地日曆日計算
- `SectionList`；分組邏輯為純函式 `groupByDate(entries, now)`，可單元測試
- 回到前景、跨過午夜時重新分組；分頁載入時，同一天的紀錄合併在同一個標題下，不出現重複標題

### F4 搜尋
- 比對欄位：乾淨網址、網站名稱、帳號、**附帶文字**（`context_text`，見下）
- **附帶文字**：處理時，輸入的文字裡除了網址之外的部分。例如從其他 App 分享進來的「【影片標題】https://youtu.be/…」，存下「【影片標題】」。這是使用者手機上本來就有的文字，不需要連網
  - 去掉網址後 trim，最多存 300 字；只有網址時存 `NULL`
  - 自動處理剪貼簿時，改為把**整段剪貼簿文字**交給清理流程（目前只傳網址），附帶文字才存得到
  - 隱私政策 p4 補充：歷史會一併保存連結旁邊的文字
- SQL：參數綁定，`LIKE ? ESCAPE '\'`，跳脫 `%`、`_` 和 `\` 本身；只選列表需要的欄位，不讀 `removed_json`、`hops_json`
- 輸入停止約 200ms 後查詢；每次查詢帶世代編號，**較舊的查詢結果回來時直接丟棄**
- 效能：先以 5,000 筆在低階 Android 真機量測。超過約 100ms 再評估 SQLite FTS5，不預先導入

### F5 保留筆數
- `HISTORY_LIMIT` 由 200 改為 5,000，與 `isPro` 無關
- 列表改為**游標分頁**：依 `(created_at DESC, id DESC)` 排序，一次 100 筆，用上一頁最後一筆的 `(created_at, id)` 取下一頁；不用 `OFFSET`。建立對應索引
- 搜尋條件改變時，游標重設

### F6 匯出 CSV（Pro）
- 歷史頁右上選單 →「匯出」，範圍：**全部**，或**目前搜尋結果**（有搜尋時才出現）。開始前顯示筆數
- 欄位白名單：日期時間、網站、帳號、**清理後網址**、狀態、移除的參數**名稱**（不含值）、附帶文字
- **不匯出**原始網址、參數的值、跳轉紀錄
- 文案稱「清理後網址」而非「乾淨網址」，並提醒：清理後的網址仍可能是私人連結。狀態不是「已清理」的紀錄（例如未能展開的短網址）在 CSV 標示出來
- 試算表公式防護：任何欄位若以 `=`、`+`、`-`、`@`、Tab、CR 開頭，前面加 `'`。測試確認 `@handle` 在 Excel、Numbers、Google 試算表顯示正常
- CSV 正確處理逗號、引號、換行；UTF-8 加 BOM
- 分批讀取、逐批寫入檔案，不一次組成整個字串；可取消
- 檔案放在 App 的 cache 目錄；分享流程結束（含取消）後刪除，下次啟動時也清掉殘留。交給其他 App 後的副本無法收回，匯出前提示
- 隱私政策補充：匯出時，資料會交給使用者選擇的 App
- 新增 `expo-file-system`、`expo-sharing`（Expo 官方套件）

## 4. 資料結構與遷移

### 4.1 新欄位
| 欄位 | 型別 | 說明 |
|---|---|---|
| `site` | TEXT NULL | F1 的顯示名稱，寫入時計算 |
| `author` | TEXT NULL | F2 的帳號，寫入時計算 |
| `context_text` | TEXT NULL | F4 的附帶文字 |

新增索引：`(created_at DESC, id DESC)`。

### 4.2 遷移（可重複執行）
- 每個欄位先用 `PRAGMA table_info(history)` 檢查，不存在才 `ALTER TABLE ADD COLUMN`。中途失敗，下次啟動會從缺的欄位接著做
- `migrate()` 在啟動路徑上，**只做這些很快的結構變更**，不做資料回填

### 4.3 舊資料回填（背景、可中斷）
- App 啟動完成後，在背景每批 200 筆，把 `site` 為 `NULL` 的舊紀錄補上 `site`、`author`
- 單筆解析失敗就寫入網域、`author` 留空，不中斷整批
- 回填期間，列表顯示時對 `site` 為 `NULL` 的紀錄**即時計算**；搜尋可能暫時找不到尚未補齊的舊紀錄（可接受，回填很快會完成）
- 舊紀錄沒有附帶文字，`context_text` 維持 `NULL`
- 對照表日後更新，**不重新回填**舊紀錄（YAGNI）

## 5. 付費狀態（isPro）
- 目前程式裡**還沒有** `isPro`。本設計只用它決定「匯出」按鈕能不能用；**沒有任何刪除行為依賴它**
- 購買、恢復購買、離線時的狀態快取，由「內購」設計處理
- 開發期間預設 `false`；debug build 有開關可以測試 Pro 功能，不放進正式版

## 6. 不在本設計範圍：標題與預覽圖
需要連到目標網站下載網頁（Open Graph），與「不連目標網站」的承諾衝突；FB、IG、Threads 常常只回傳登入頁，小紅書在台灣被封鎖。若要做，另開設計，至少要：預設關閉、只用清理後網址抓、更新隱私政策。F4 的附帶文字可以先解決大部分「找不到內容」的問題。

## 7. 讀取的健壯性
- 每筆紀錄獨立轉換：`removed_json`、`hops_json` 解析失敗，**或解析出來不是陣列**（例如 `null`、`{}`），就用空陣列代替，保留網址和日期，不讓整個清單失敗。列表、詳情頁、匯出共用同一個轉換
- 資料庫查詢本身失敗時，顯示錯誤訊息和「重試」，**不要顯示成「沒有紀錄」**（目前的行為會讓人以為資料被刪了）

## 8. 測試
- 單元測試（vitest）：
  - `describeLink`：每個平台的正確樣式、保留路徑（`/explore/`、`/i/status/`、`/groups/…/posts/`）、假網域（`instagram.com.evil.test`）、子網域、空字串、無效網址、錯誤的百分比編碼
  - `groupByDate`：跨午夜、跨月、跨年、夏令時間
  - 附帶文字：只有網址、網址在前／後／中間、超過 300 字
  - `migrate`：全新安裝、舊表、部分欄位已存在、重複執行
  - 回填：中斷後繼續、壞網址
  - 搜尋：網址、網站、帳號、附帶文字；`%`、`_`、`\`、`'` 輸入
  - 游標分頁：分頁之間新增或刪除紀錄，不重複、不遺漏
  - 壞資料：`removed_json` 為非 JSON、`null`、`{}`
  - CSV：逗號、引號、換行、中文、BOM、公式開頭字元、`@handle`、欄位白名單（不含原始網址與參數值）
- 手動（Android 真機 + iOS 模擬器）：分組、搜尋、5,000 筆時的捲動和搜尋速度（低階 Android 真機）、匯出到檔案 App、取消匯出後沒有殘留檔

## 9. 範圍外
- 標題與預覽圖（第 6 節）
- 記錄「真的分享了」的事件
- 標籤、收藏、備註
- 雲端同步、跨裝置
- 統計（例如「本月處理最多的網站」）
