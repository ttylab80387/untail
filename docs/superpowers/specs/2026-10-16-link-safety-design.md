# 連結安全檢查與隱藏字元清除 — 設計文件

- 日期：2026-10-16
- 狀態：待審閱
- 目標版本：分三階段（見第 7 節），第一階段可放進第一版

## 1. 目標

### 1.1 為什麼要做
使用者本來就會把陌生連結丟進 Untail 清理。在同一個畫面順便提醒「這個連結有可疑之處」，不需要多一個步驟，也延伸了 Untail 的定位：從「清掉追蹤碼」擴大成「**分享前檢查一下**」。

兩個需求：
1. **隱藏字元**：網址或文字裡夾帶看不見的字元（零寬空格、方向控制字元等），可能讓連結打不開、被用來辨識複製者，或用來偽裝網址
2. **詐騙／偽造網址**：假冒品牌、外文字母偽裝、已知詐騙網域

### 1.2 原則
- **連結不離開手機**：所有檢查都在手機上做。詐騙清單由 GitHub 每天打包，App 下載整份清單後在本機比對，和現在的規則更新方式相同
- **永遠不說「安全」**：新的詐騙網站常常只存在幾天，清單一定有漏網之魚。沒發現問題時只說「沒有發現已知風險」，並清楚顯示真正的網域，讓使用者自己判斷
- **提醒，不是判定**：特徵檢查會誤判正常網站，文案用「可能」、「請留意」，並提供「回報誤判」
- **安全功能全部免費**：拿防詐騙收費，既不合理也會傷害評價

## 2. 功能總覽

| # | 功能 | 需要的資料 | 適用地區 |
|---|---|---|---|

## 3. 各功能細節

### S1 清除網址裡的隱藏字元
- 在 `@linkclean/core` 擷取網址前，先找出並移除下列字元：
  - 零寬字元：U+200B、U+200C、U+200D、U+2060、U+FEFF
  - 軟連字號 U+00AD
  - 方向控制字元：U+200E、U+200F、U+202A–U+202E、U+2066–U+2069
  - Unicode 標籤字元 U+E0000–U+E007F
- **只處理網址本身**，不動網址以外的文字；網址裡不會有正常需要這些字元的情況
- 被移除的字元加入「已移除」清單，類別為 `hidden`（三語說明：「看不見的字元，可能讓連結失效或被用來辨識是誰複製的」）
- **方向控制字元出現在網址裡時**，另外標成 S3 的高風險特徵：這是常見的偽裝手法（讓 `evil.com/moc.elgoog` 看起來像 `google.com`）

### S2 顯示真正的網域
- 用公共後綴清單（Public Suffix List）算出「可註冊網域」：`shopee.tw.secure-login.xyz` → `secure-login.xyz`；`news.bbc.co.uk` → `bbc.co.uk`
- 使用 `tldts` 套件（MIT 授權，內建 PSL，純 JS，可離線）
- 結果卡上方新增一行：**「網域：secure-login.xyz」**，粗體顯示可註冊網域，子網域用淡色
- 國際化網域（`xn--` 開頭）同時顯示解碼後的字和 `xn--` 原文
- 短網址和外連包裝：顯示的是**最終**網域；跳轉紀錄裡每一站的網域也都要經過 S3、S4 檢查

### S3 網址特徵檢查
純函式 `inspectUrl(url, data)`，回傳「發現」清單，每項有等級（`high` / `caution`）和原因代碼。

| 原因代碼 | 等級 | 判斷方式 | 例子 |
|---|---|---|---|
| `userinfo` | high | 網址含 `@` 前的帳號欄位 | `https://shopee.tw@evil.com` |
| `bidi` | high | 網址有方向控制字元（見 S1） | |
| `brand-in-subdomain` | high | 品牌網域出現在子網域或路徑，但可註冊網域不是該品牌 | `shopee.tw.secure-login.xyz` |
| `lookalike` | high | 可註冊網域與品牌網域只差 1 個字元，或只差在形近字元（0/o、1/l/i、rn/m） | `paypa1.com`、`faceb00k.com` |
| `mixed-script` | high | 網域混用不同文字系統，且其中有與拉丁字母形近的字元 | `аpple.com`（俄文 а） |
| `brand-keyword` | caution | 品牌名稱出現在可註冊網域裡，但不是官方網域 | `shopee-tw-login.top` |
| `ip-host` | caution | 主機是 IP 位址 | `http://203.0.113.5/login` |
| `risky-tld` | caution | 常被濫用的頂級網域（清單放規則檔，可更新） | `.top`、`.icu`、`.xyz` |
| `punycode` | caution | 國際化網域，但沒有混用文字系統 | `xn--…` |

- **品牌清單**放在規則檔（`rules/brands.json`），可透過規則更新：品牌名稱、官方可註冊網域列表、比對用關鍵字
  - 初版以台灣常見、常被冒充的為主：蝦皮、LINE、Facebook、Instagram、Google、Apple、PayPal、momo、PChome、中華郵政、各大銀行、國稅局／政府（`gov.tw`）；再加上全球常見的 Amazon、Microsoft、Netflix 等
  - 官方網域要完整列出（例：蝦皮 `shopee.tw`、`shopee.com`），避免把官方網站判成冒充
- `risky-tld` 只算提醒，不單獨構成高風險
- `lookalike` 只比對品牌清單，不比對全世界的網站，避免誤判

### S4 比對已知詐騙網域
- **資料來源**（GitHub Actions 每天抓，有變動才發布）：
  - 台灣：165「遭停止解析涉詐網站」（data.gov.tw 176455，約 9.4 萬筆）與「假投資（博弈）網站」（160055）。政府資料開放授權第 1 版，需在 App 的授權頁與 NOTICE 註明出處
  - 全球：Phishing.Database 的 `phishing-domains-ACTIVE`（MIT，約 39 萬筆）
  - JPCERT/CC（日本）授權不明，**本設計不納入**，確認授權後再加
  - Google Safe Browsing：限非商業使用，且要求警告前 30 分鐘內同步過，**不採用**
- **檔案大小**：原始清單太大（全球清單 11 MB）。改為只發布**網域雜湊**：每個網域取 SHA-256 的前 48 位元，排序後存成二進位檔
  - 台灣約 0.6 MB、全球約 2.4 MB；48 位元下誤判機率約十億分之一
  - 獨立於 `rules.json`，各自有 sha256，只在內容變動時下載
  - 全球清單更新頻繁，**每週發布一次**，避免每天下載 2.4 MB
- **比對**：對網址的主機名稱，以及往上到可註冊網域為止的每一層（`a.b.example.com` → `a.b.example.com`、`b.example.com`、`example.com`）計算雜湊，用二分搜尋查表
- **App 端**：清單存成檔案，啟動時讀進記憶體（`Uint8Array`，約 3 MB）。不放進 SQLite
- **下載設定**：台灣清單預設下載；全球清單在「設定 → 下載國際詐騙網站清單（約 2.4 MB）」，**預設開啟，但只在 Wi-Fi 下更新**
- 命中時顯示來源：「這個網域在台灣警政署的涉詐網站清單上（2026 年 9 月）」或「這個網域在國際釣魚網站清單上」

### S5 清除整段文字的隱藏字元
- 首頁新增「文字模式」：貼上一整段文字（不只是網址），列出找到的隱藏字元（位置、名稱），按「清除並複製」
- **保留必要的字元**：
  - emoji 組合裡的零寬連接符（ZWJ，例如 👨‍👩‍👧）與異體字選擇符（U+FE0F 等）
  - 阿拉伯文、希伯來文段落裡的方向控制字元
  - 判斷方式：ZWJ 前後都是 emoji 才保留；方向控制字元只在文字含右至左文字時保留
- 形近字（俄文、希臘字母）**只提示不替換**，避免改壞外文
- 不宣稱能去除 AI 浮水印：大部分 AI 浮水印藏在用字選擇裡，不是隱藏字元

## 4. 畫面

- **結果卡**（S2–S4）：
  - 狀態列下方新增「網域」一行（S2）
  - 有 `high` 發現或命中 S4 時，結果卡最上方顯示**紅色警告區塊**：標題「這個連結可能是詐騙」，列出原因（白話說明，例：「網址看起來像蝦皮，但實際網站是 secure-login.xyz」）
  - 只有 `caution` 時，顯示**橘色**「請留意」區塊
  - 沒有發現時：不加任何區塊，只在網域那行旁邊淡淡標註「沒有發現已知風險」
  - 警告區塊內有「回報誤判」，沿用現有的回報郵件
- **自動處理與分享**：有紅色警告時，仍然清理和複製（使用者可能是要轉傳給別人提醒），但「已換成乾淨連結」的通知改成紅色，並附上警告原因
- **歷史紀錄**：有警告的紀錄顯示紅色或橘色標記（與歷史改版設計一起做）

## 5. 資料與隱私

- 規則網站新增 `blocklist-tw.bin`、`blocklist-global.bin` 與各自的 meta（版本、筆數、sha256、資料日期）
- 下載與比對都在手機上；連結不會送到任何地方。隱私政策補充：「App 會下載公開的詐騙網域清單，在手機上比對，不會傳送你的連結」
- NOTICE 與授權頁新增：165（政府資料開放授權第 1 版）、Phishing.Database（MIT）、tldts（MIT）、Public Suffix List（MPL 2.0）

## 6. 測試

- 單元測試：
  - S1：每一類隱藏字元、網址中間／結尾、方向控制字元觸發 `bidi`
  - S2：多層子網域、`co.uk` 這類兩層後綴、國際化網域、IP、無效網址不拋錯
  - S3：每個原因代碼的正例和反例；**官方網域不能被判成冒充**（`shopee.tw`、`m.facebook.com`、`l.facebook.com`）；常見正常網站（`news.ltn.com.tw`、`github.io` 底下的網站）不能出現 high
  - S4：雜湊格式、二分搜尋、子網域往上比對、清單不存在時不出錯
  - S5：emoji 組合保留、右至左文字保留、零寬字元移除
- 回歸測試：把 Untail 目前所有測試網址跑一次 S3，確認沒有誤判
- 建置流程測試：165 CSV 欄位改名或檔案損壞時，**不發布**壞掉的清單，沿用前一版

## 8. 需要注意的地方（Review Focus）

1. **誤判官方網站**：例如把 `l.facebook.com`、`shopee.com.my` 判成冒充，會讓使用者不信任整個功能
2. **漏判時的語氣**：任何文案都不能讓人以為「沒警告就是安全」
3. **165 資料格式變動**：政府資料欄位或編碼可能改變，建置流程要能偵測並拒絕發布
4. **清單過期**：手機長時間沒更新時，要顯示清單的資料日期
5. **記憶體與啟動時間**：3 MB 的清單載入不能拖慢冷啟動（可延後到第一次需要比對時再載入）

## 9. 範圍外

- 把網址送到外部服務即時查詢（違反隱私原則）
- 開啟網頁檢查內容（例如偵測假登入頁）
- 檢查 LINE ID、電話號碼等非網址的詐騙資訊
- 日本 JPCERT 清單（授權確認後再加）
