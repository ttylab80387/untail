# 連結安全檢查與隱藏字元處理 — 設計文件

- 日期：2026-10-16（同日依 codex / agy 設計審查修訂）
- 狀態：待審閱
- 目標版本：分三階段（見第 8 節）

## 1. 目標

### 1.1 為什麼要做
使用者本來就會把陌生連結丟進 Untail。在同一個畫面提醒「這個連結有容易混淆的地方」，不需要多一個步驟，也把 Untail 從「清掉追蹤碼」延伸成「**分享前檢查一下**」。

兩個需求：
1. **隱藏字元**：網址夾帶看不見的字元，可能讓連結打不開、被用來辨識複製者，或用來偽裝網址
2. **詐騙／偽造網址**：冒充品牌的網域、形近字偽裝、已被公開清單收錄的網域

### 1.2 原則
- **連結不會為了「檢查」而送出去**：特徵檢查與清單比對都在手機上做；清單由 GitHub 打包，App 下載整份後在本機比對。**短網址展開本來就會連線**（隱私政策 p3 已說明），本設計會讓展開更保守（見 S0）
- **永遠不說「安全」，也不指控**：
  - 沒發現問題：「未命中已下載的清單；不代表安全」
  - 特徵：「網址含有容易混淆的格式」＋具體事實
  - 清單命中：「此網域出現在［來源］的［清單］中（資料日期）」
  - 不使用「這是詐騙」、「可能是詐騙」這類指控字眼
- **先求不誤判，再求抓得多**：寧可少抓，也不要讓正常網站被標紅，否則使用者很快就會無視警告
- **安全功能全部免費**

## 3. S0 網址解析與展開

### 3.1 一致的主機解析（修正既有問題）
- 現有 `getHost()`（`packages/core/src/query.ts`）用正規表示式取主機，與瀏覽器不一致。實測：

  | 輸入 | 現有 `getHost()` | 瀏覽器（`URL.hostname`） |
  |---|---|---|
  | `https://evil.example\@shopee.tw/x` | `shopee.tw` | `evil.example` |
  | `https://one.example@two.example@evil.example/` | `two.example` | `evil.example` |
  | `https://[2001:db8::1]/` | `[2001` | `[2001:db8::1]` |

- 改為：主機一律用 WHATWG `URL` 解析（Hermes 支援；不支援時以 polyfill 補上），**規則比對、顯示、清單比對、網路請求都用同一個結果**
- 只用來取主機，不把整條網址重新序列化輸出，避免改壞簽章或編碼
- 這個修正也會影響現有的追蹤碼規則比對（哪個網站套用哪些規則），要跑完整回歸測試

### 3.2 逐站展開
- 現在多數短網址用 `redirect: 'follow'`，中間的轉址看不到，而且手機可能已經連到非白名單的目的地
- 改為**每一站都用 `redirect: 'manual'` 讀 `Location`**，在發出下一個請求前，先對下一站做 S4 比對與 S3 高風險檢查：
  - 命中清單或高風險 → **停止展開**，顯示已取得的目的地
  - 下一站不在短網址白名單、也不是同一平台的轉址 → 停止，不連到目標網站
- 保留整體逾時與最多跳數限制
- 展開停用、失敗或沒有走完時，畫面寫「目前取得的目的地」，不寫「最終網域」
- 相容性：FB／Threads 的分享連結目前依賴 follow 才拿得到最終網址；改用逐站展開時，以 `cases.json` 回歸測試確保結果不變，必要時為該平台允許同網域內的多次轉址

### 3.3 所有網址都要檢查
- 現在剪貼簿流程用 `needsCleaning()` 決定要不要處理；**沒有追蹤碼的可疑連結會直接被說成「本來就是乾淨的，可以直接分享」**
- 改為：所有讀取到的網址都經過 S2–S4。`ProcessResult` 分開記錄：清理狀態、安全檢查是否完成、發現項目、使用的清單版本
- 「本來就是乾淨的，可以直接分享」改成「沒有找到追蹤碼」，不再暗示可以放心分享

## 4. S1 網址隱藏字元

### 4.1 先修擷取的邊界問題
- `extractUrl()` 遇到 U+FEFF 會截斷網址（`https://example.com/a<FEFF>b` 只取到 `/a`）
- 把全形句點 `。` 當成句尾，會截斷 `https://example。com/`（`。` 是合法的網域分隔符）
- 改為：先取得含隱藏字元的完整候選網址，並記錄每個字元的位置，再分別產生「檢查用」和「輸出用」兩個版本

### 4.2 處理方式：偵測一律做，修改很保守
| 字元 | 位置 | 處理 |
|---|---|---|
| U+200B 零寬空格、U+FEFF、U+2060、U+00AD 軟連字號 | 任何位置 | **移除**，列入「已移除」 |
| U+202A–U+202E 方向嵌入／覆寫 | 任何位置 | **移除**，並標成高風險特徵（常見的偽裝手法） |
| U+200E、U+200F、U+2066–U+2069 方向標記／隔離 | 主機名稱 | 移除並標示 |
| 同上 | 路徑、查詢、片段 | **保留**，只顯示「含有方向控制字元」 |
| U+200C ZWNJ、U+200D ZWJ | 主機名稱 | **不移除**：合法國際化網域需要（UTS #46）。只顯示提示 |
| 同上 | 路徑、查詢、片段 | **保留**（波斯文、emoji 需要），只提示 |
| U+E0000–U+E007F 標籤字元 | 任何位置 | 移除並標示 |

- 百分比編碼（`%E2%80%8B`）只偵測、不解碼修改
- 「已移除」清單新增類別 `hidden`，三語說明：「看不見的字元，可能讓連結失效或被用來辨識是誰複製的」

## 5. S2 主機名稱與主要網域

- 用 `tldts`（MIT，內建 Public Suffix List）從 S0 的主機算出主要網域，**開啟 `allowPrivateDomains`**，讓 `alice.github.io`、`bob.github.io` 被視為不同的網站
- 結果卡新增一行：**「網站：secure-login.xyz」**，主要網域粗體，子網域淡色
- 國際化網域同時顯示解碼後的文字和 `xn--` 原文，**不視為風險**
- IP、只有公共後綴、未知後綴、解析失敗各自顯示，不拋錯
- 用詞是「網站」或「主要網域」，不暗示能證明網站的身分

## 6. S4 比對公開清單

### 6.1 資料來源
| 來源 | 範圍 | 授權 | 粒度 | 階段 |
|---|---|---|---|---|
| 165「遭停止解析涉詐網站」（data.gov.tw 176455，約 9.4 萬筆，每月更新） | 台灣 | 政府資料開放授權第 1 版 | 網域（含其所有子網域） | 2 |
| 165「假投資（博弈）網站」（160055） | 台灣 | 同上 | 主機 | 2 |
| Phishing.Database `phishing-domains-ACTIVE`（約 39 萬筆） | 全球 | MIT | 主機（精確） | 3 |

不採用：Google Safe Browsing（限非商業使用，且要求警告前 30 分鐘內同步）、URLhaus（授權不明確）、JPCERT（找不到授權條款）。

### 6.2 建置流程（GitHub Actions）
- 每個來源一個 adapter，有保存好的 fixture 測試
- 驗證：HTTP 狀態、檔案格式（不是 HTML 錯誤頁）、編碼、必要欄位、有效紀錄比例、筆數與前一版的變動幅度、資料日期沒有倒退
- 正規化：去掉協定和路徑、轉小寫、IDNA 轉 ASCII、去掉結尾的 `.`、處理 `hxxp`、`[.]` 這類去武裝寫法；無法解析的紀錄丟棄並計數
- **永不封鎖清單**（`rules/never-block.json`）：公共後綴本身、主要平台與品牌的官方網域、多租戶平台的根網域（`github.io`、`pages.dev`、`blogspot.com` 等）。清單中的紀錄若落在這裡，**丟棄並在建置紀錄中列出**，由維護者人工確認
- 異常時：該來源**不發布新版**，保留最後一個有效版本，並**開 GitHub Issue 通知**；連續 7 天抓取失敗也開 Issue，避免靜默過期
- 來源的刪除（例如誤列的網站被移除）要能傳到 App：每版都是完整重建，不是只增不減
- 165 的舊紀錄：只保留最近 24 個月列入的網域，降低網域被別人重新註冊後誤判的風險

### 6.3 檔案格式
- 只發布雜湊：正規化後的主機（ASCII、小寫、無結尾點）→ SHA-256 → 取前 **64 位元**（8 bytes），依位元組排序
  - 64 位元下，單次比對誤中機率約 2.6 × 10⁻¹⁴，可以忽略
  - 台灣約 0.75 MB、全球約 3.1 MB
- 每筆附一個旗標：精確主機，或含所有子網域
- meta：格式版本、正規化版本、筆數、檔案 sha256、**上游資料日期**、建置時間
- 獨立於 `rules.json`，各自依 sha256 判斷是否需要下載

### 6.4 App 端
- 下載到暫存檔，驗證 sha256 後才替換舊檔；失敗就保留前一版
- 第一次需要比對時才讀進記憶體（`Uint8Array`），之後重複使用；不在冷啟動時載入
- 比對：主機本身，以及往上到主要網域為止的每一層；上層的紀錄只有標成「含所有子網域」才算命中，而且**不跨越多租戶平台的邊界**
- 用位元組直接比較，不用 JS 位元運算組 64 位元整數（會被截成 32 位元）
- 清單狀態要能顯示：未下載、已下載（資料日期）、過期（超過 45 天沒更新）、更新失敗
- 全球清單：每天在網站上更新；App 預設只在 Wi-Fi 下更新，設定裡可以手動用行動網路更新
- 分享進來的連結由主 App 處理（expo-share-intent 不在分享延伸程式內執行 JS），所以不用擔心延伸程式的記憶體限制

## 7. S3 特徵檢查（階段 3，先少量上線）

初版只做這幾項，其他延後：

| 代碼 | 等級 | 判斷 | 文案（中文） |
|---|---|---|---|
| `bidi-host` | 高 | 主機名稱有方向控制字元 | 網址含有改變顯示方向的隱藏字元 |
| `userinfo` | 注意 | 網址有帳號欄位（依 S0 解析） | 網址開頭看起來像 X，但實際連到 Y |
| `brand-subdomain` | 注意 | 品牌的官方網域以**完整標籤**出現在子網域，例如 `shopee.tw.secure-login.xyz`；**不檢查路徑** | 網址裡有「shopee.tw」，但實際網站是 secure-login.xyz |
| `confusable` | 高 | 主要網域的 confusable skeleton（UTS #39）等於某個品牌的官方網域，但不是該品牌 | 網域和「paypal.com」長得很像，但不是同一個 |

- **品牌資料**（`rules/brands.json`）：官方主機（精確）、官方網域（含子網域）、命名空間規則（例如 `gov.tw`）分開記錄，附來源與維護日期。官方例外**只抑制該品牌的冒充檢查**，不跳過清單比對
- **延後或不做**：一般編輯距離比對（短品牌誤判太多）、品牌關鍵字子字串比對（`line`、`apple` 是普通字）、可疑頂級網域（`.xyz` 有大量正常網站）、單純使用 IP 或國際化網域
- 上線前用一批正常網址（各地區官方網站、CDN、合法國際化網域、多租戶平台、新聞與封存服務的路徑）量測誤判，每一項分開記錄

## 8. 畫面與行為

- **結果卡**：
  - 狀態列下方：「網站：…」（S2）
  - 清單命中：紅色區塊，寫明來源、清單名稱、資料日期，以及命中的是主機本身還是上層網域
  - 高風險特徵：紅色區塊，列出事實
  - 注意等級：橘色區塊
  - 沒有發現：只在網站那行旁邊淡淡寫「未命中已下載的清單；不代表安全」
  - 清單未下載、過期、展開未完成：灰色說明，例如「尚未完成清單比對」
  - 顏色之外一定有圖示和文字，不只靠顏色區分
- **自動處理、自動複製**：清單命中或高風險時，**不自動複製**，剪貼簿保持原樣；結果卡提供「仍要複製」。通知寫明原因
- **回報誤判**：預設只帶主機、原因代碼、清單來源和版本；完整網址由使用者在郵件草稿裡自己決定要不要加上（目前的回報會帶完整網址，可能含有私人資訊）
- **歷史紀錄**：有警告的紀錄顯示標記（與歷史改版一起做）

## 9. 隱私與授權

- 隱私政策：說明 App 會下載公開的清單，在手機上比對，**檢查本身不會傳送你的連結**；短網址展開照舊會連到短網址服務，並說明新的逐站展開方式
- NOTICE、App 授權頁，以及網站上發布的清單檔都附上：來源、授權連結、「經過正規化與雜湊轉換」的說明；Phishing.Database 保留 MIT 著作權與授權全文；tldts（MIT）、Public Suffix List（MPL 2.0）

## 10. 測試

- S0：上表三個解析案例、IPv6、帳號欄位、反斜線；逐站展開在每一站命中清單時會停止；`cases.json` 全部照舊通過
- S1：每類字元在主機和路徑的處理；FEFF 不再截斷；`。` 分隔的網域；合法國際化網域（含 ZWNJ）不被改變；百分比編碼不被修改
- S2：`co.uk` 等兩層後綴、`github.io` 私有後綴、PSL 萬用字元與例外、IP、只有後綴、無效網址
- S4：雜湊與排序格式、精確與子網域旗標、不跨多租戶邊界、清單不存在／過期；建置 adapter 的 fixture（BOM、引號內逗號、HTML 錯誤頁、欄位錯位、筆數暴增或暴減、日期倒退）；永不封鎖清單生效
- S3：每項的正例與反例；官方網域不被標示；誤判量測集
- 整體流程：沒有追蹤碼的可疑連結也會被檢查；命中時不自動複製；回報內容預設不含完整網址

## 12. 需要注意的地方（Review Focus）

1. **誤判正常網站**：官方網域、地區站、多租戶平台、合法國際化網域
2. **安全背書**：任何文案都不能讓人以為「沒警告就是安全」
3. **改壞網址**：S1 和 S0 不能改變合法網址指向的目的地
4. **資料品質**：上游格式變動、靜默過期、誤列網域的移除
5. **展開行為改變**：FB、Threads、小紅書等現有的展開結果不能退步

## 13. 範圍外

- 開啟網頁檢查內容（例如偵測假登入頁）
- LINE ID、電話號碼等非網址的詐騙資訊
